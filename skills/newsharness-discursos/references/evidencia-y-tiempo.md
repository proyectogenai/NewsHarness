# Evidencia fechada, versiones y reutilización

## Cuatro tiempos que no deben confundirse

1. **Declaración:** cuándo se emitió la pieza; si sólo lo afirma el documento aportado, indicarlo.
2. **Referencia:** período que mide la cifra o al que se refiere el hecho.
3. **Publicación/revisión:** cuándo la fuente puso esa versión a disposición y cuándo la modificó.
4. **Consulta:** cuándo se accedió efectivamente a ella para este trabajo.

No rellenar una fecha desconocida con la fecha de consulta. Una fecha de acceso no acredita cuándo se publicó el dato. En un análisis histórico, establecer el corte informativo y mantener separados «lo que se conocía entonces» y «lo que sabemos por revisiones posteriores». Si no se pudo recuperar una versión histórica, declararlo; no asegurar que una versión actual existía entonces.

## Registro de una evidencia reutilizable

Mantener un ID de fuente y un ID/versionado de la evidencia, referencia consultable, autor u organismo, tipo de fuente, título, ubicación precisa, fechas, período, unidad, método y nota de vigencia. Para archivos locales, usar una ruta controlada y hash; no guardar claves, cookies o enlaces con credenciales. Si no puede verificarse publicación o revisión, conservar el valor desconocido y describir el límite.

La vigencia no es un sello universal: una tabla puede seguir siendo útil para 2024 y haber sido reemplazada para otra pregunta. Antes de reutilizar una entrada:

- comprobar acceso, versión y posibles correcciones;
- confirmar que unidad, definición, universo y período coinciden con la nueva afirmación;
- identificar si sostiene, contradice o sólo contextualiza esa afirmación;
- registrar la nueva consulta y no borrar la versión previa;
- separar cálculos propios de cifras publicadas, mostrando fórmula e insumos.

No declarar que una fuente es independiente sólo porque tiene otra URL. Detectar republicaciones y origen común. Una fuente oficial puede probar lo que registró o declaró, pero puede no resolver subregistro, cobertura, errores o causalidad. Un documento inaccesible o un snippet no leído íntegramente no se convierte en evidencia completa.

## Discrepancias y causalidad

Mostrar definiciones, fecha de extracción, ajustes y revisiones antes de explicar una diferencia. Si la explicación no pudo establecerse, presentarla como hipótesis, no como hecho. Una causa requiere una pregunta definida y una estrategia que permita distinguirla de alternativas; ni «ocurrió después» ni «ambas series se movieron juntas» la establecen.

## Ausencias y límites

«No encontrado» describe la búsqueda, no la realidad. Una ausencia sólo puede aportar evidencia negativa si el registro debería contener el evento, el universo está definido, la cobertura es suficiente y se documentó qué se revisó. Si eso no se cumple, el resultado queda no resuelto.

## Lo que no hace este módulo

Los registros son archivos locales revisables. No hay base de datos persistente gestionada, sincronización, actualización programada, descarga histórica automática ni archivo público automático. Una futura integración con servicios o biblioteca externa requiere su propio alcance y autorización.
